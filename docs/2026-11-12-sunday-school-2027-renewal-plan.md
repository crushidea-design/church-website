# 2027 주일학교 개편에 따른 다음세대 페이지 리뉴얼 계획

- 작성일: 2026-11-12
- 근거 문서: 「2027 주일학교 개편 및 운영 계획안」(docx)
- 목표 공개일: **2027-01-03 신년주일(개강 주일)**. 단, 학기제·2교시 등 당회 승인 사항은 승인 후 공개한다.
- 범위: `/next` 다음세대 사이트(소개, 부서 자료실, 하이라이트 밴드, 마이페이지, 관리자 CMS). 청년부는 기존 운영을 유지한다.

## 1. 개편안이 페이지에 요구하는 변화

| 개편안 내용 | 현재 페이지 | 페이지에 필요한 변화 |
|---|---|---|
| 유초등부 + 중고등부 → **하나의 주일학교** | 부서 카드: `유초등부`(elementary), `청년부`(young-adults) | 부서 이름·소개를 `주일학교`로, 중고등 학생까지 포괄 |
| 반 편성 **씨앗·자람·세움·디딤** (골 2:6-7) | 반 개념은 말씀 열매 그룹(`next_generation_word_fruit_groups`)과 출석에만 있음 | 반을 공개 소개와 자료 분류의 1급 개념으로 승격 |
| 교재 **하이델베르크 요리문답 2년 과정**(52주일, 129문) | 주제 카탈로그: 십계명·성경·사도신경 | 주제를 "하이델베르크 제N주일" 단위로 교체, 진도 표시 |
| 공통 강해 1종 + **반별 공과 3종**(자람·세움·디딤) + 씨앗반 찬송·동화 | 강의원고·공과·공과가이드·예배를 잇는 가정 각 1종 | 공과를 반별로 나누고, "이번 주 자료"에 반별로 표시 |
| **학기제**(학기 20주·방학 6주), 휴강 주일 | 매주 같은 화면(`getCurrentSundayKey`) | 학사 일정 데이터 + 학기 중/방학 중/휴강 화면 모드 |
| 방학 = **가정 신앙교육 집중 기간** | 가정예배·예배를 잇는 가정이 하이라이트 밴드 3번째 | 방학 중에는 가정 자료가 첫 화면의 주인공 |
| 「예배를 잇는 가정」 뒷면: 학기 중 "오늘 강의 중에서" / 방학 "오늘 공예배 중에서" | 단일 탭 `family_column` | 같은 탭 안에서 판(학기/방학) 구분 표시 |
| 주일 **1교시·공예배·2교시** 시간표 | 소개 문구에 "10시 모임 → 11시 공예배"만 있음 | 시간표 블록 신설 |
| 개강 수련회, **여름방학캠프**(여름성경학교 대체) | `summer_bible_school` 탭 | 행사 탭을 "수련회·캠프"로 개편 |
| 2교시 참여율, 방학 중 공예배 출석, 가정 과제 참여로 **학기 평가** | 출석은 주별 `present: boolean` 하나 | 1교시/2교시/공예배 구분 출석 + 학기 평가 리포트(관리자 전용) |

## 2. 정보 구조(IA) 제안

### 2-1. 상단 메뉴

```
다음세대 소개 | 주일학교 | 청년부 | 문의하기
```

- `유초등부` → `주일학교`로 이름만 바꾸는 것이 아니라, 아래 2-2의 새 홈 구조로 바꾼다.

### 2-2. 주일학교 홈 (`/next/school`) — 위에서 아래 순서

1. **히어로 — "이번 주일" 카드** (학사 일정에 따라 모드가 바뀜)
   - 학기 중: `1학기 · 제7회 · 하이델베르크 제6주일 16~17문 「참 사람이시며 참 하나님이신 중보자」` + 공예배 시편 찬송, 성찬 주일 표시(2교시 단축)
   - 휴강 주일: `설 연휴로 주일학교 수업이 없습니다. 공예배는 함께 드립니다.`
   - 방학 중: `여름방학 3주차 — 공예배와 가정 신앙교육 집중 기간` + 이번 주 「예배를 잇는 가정」·가정예배지 바로가기
2. **2년 과정 진도 막대**: 위로 → 비참 → 구원 → 감사, 현재 위치(제N주일/52) 표시
3. **반 선택 칩**: 씨앗 · 자람 · 세움 · 디딤 (로그인 사용자는 자기 반이 기본 선택)
4. **이번 주 자료** (기존 `elementary_weekly` 묶음 화면 확장)
   - 공통: 강해 원고, 「예배를 잇는 가정」, 가정예배지
   - 선택한 반: 반별 공과 / 공과 가이드 (씨앗반은 찬송·동화)
5. **하이라이트 밴드**: 질문 있습니다 · 이번 주 문답(암송) · 가정예배 나눔
6. **자료실 탭**: 아래 3장 참조
7. **학사 일정 미니 캘린더**: 개강·종강·휴강·수련회·캠프

### 2-3. 다음세대 소개 (`/next`)

현재 `IntroPage.tsx`의 기둥(예배 중심 교육 / 가정과 동행 / 성경과 교리) 문구는 **코드에 하드코딩**되어 있고, "소요리문답", "2025년 여름부터 사도신경·십계명" 같은 현행 내용이 들어 있다. 다음으로 교체한다.

- **네 가지 원칙**: 교육의 장 · 공예배 중심 · 부모의 일차 책임 · 은혜의 원리
- **표어 골 2:6-7 시각화**: 본동사 "행하라" 아래 수동 분사 세 개(뿌리 박음·세움·굳게 섬)와 능동 "감사함을 넘치게"를 한 줄 흐름으로. 그 위에 씨앗(6절) → 자람 → 세움 → 디딤(7절) 반 이름을 얹는다. "자라면서 다음 반으로 올라간다"는 설명 포함.
- **반 소개 카드 4장**: 연령 기준, 근거 구절, 운영 방식(씨앗반은 부모 동반 등). **인원·구성은 싣지 않는다**(4-3 참조).
- **주일 시간표**: 10:00 1교시 → 11:00 공예배 → 12:25 2교시 → 13:20 마침
- **학기제 안내**: "방학은 쉬는 기간이 아니라 가정이 가르치고 교회가 돕는 기간"
- **교재 소개**: 하이델베르크 요리문답 — "위로의 교리문답", 제1문 "유일한 위로", 2년 과정 범위표
- 이 문구들은 하드코딩하지 않고 CMS 소개 섹션(`next_generation_intro_sections`)으로 옮겨 교역자가 직접 고칠 수 있게 한다.

## 3. 자료 탭 재구성

기존 게시물은 `subCategory`(탭 ID)로 분류되어 있다. **의미가 같은 탭은 ID를 유지**해 링크·주차 묶음·주제 필터가 깨지지 않게 하고, 새로 필요한 것만 추가한다.

| 탭 ID | 표시 이름 | 처리 |
|---|---|---|
| `elementary_weekly` | 이번 주 자료 | 유지, 반별 표시 로직 추가 |
| `elementary_script` | 공통 강해 원고 | 유지(이름 변경) |
| `elementary_guide` | 공과 가이드 | 유지, 반 구분 필드 추가 |
| `family_column` | 예배를 잇는 가정 | 유지, "학기판/방학판" 표시 |
| `family_worship` | 가정예배 | 유지 |
| `workbook_jaram` / `workbook_seum` / `workbook_didim` | 자람반·세움반·디딤반 공과 | **신설** |
| `seed_songs_stories` | 씨앗반 찬송·동화 | **신설** (부모 참여형 안내 포함) |
| `parent_guide` | 부모 안내 | **신설** — 개편 안내문, 방학 가정 교육 길잡이 |
| `school_events` | 수련회·캠프 | `summer_bible_school` 대체 신설 |
| `elementary_workbook`, `summer_bible_school` | (2026 자료) | 숨김 + "지난 자료" 보관함으로 이동 |

- **주제 카탈로그**: 십계명·성경·사도신경은 "2025–26 자료"로 묶어 남기고, `heidelberg-ld-01` ~ `heidelberg-ld-52` 주제를 새로 만든다. 업로드 시 주일 번호를 고르면 문 범위가 자동으로 붙는다.
- **학생 계정 제한**: 현재 `학생` 역할은 유초등부에서 공과 탭만 본다(`ResourceLibraryPage.tsx:91`). 세움·디딤반 학생은 **자기 반 공과 + 공통 강해 원고 + 질문 있습니다**까지 보도록 넓힌다. 공과 가이드(교사용 정답)는 계속 숨긴다.

## 4. 데이터 모델

### 4-1. 신규 컬렉션 (관리자 쓰기 전용, 공개 읽기)

```ts
// next_generation_school_terms — 학사 일정
{ id: '2027-1', kind: 'term' | 'vacation', name: '2027 1학기',
  startDate: '2027-01-03', endDate: '2027-06-27' }

// next_generation_school_curriculum — 주별 진도표 (계획안 8장 표를 그대로 입력)
{ weekKey: '2027-02-28', termId: '2027-1', session: 7,
  kind: 'class' | 'opening' | 'retreat' | 'review' | 'closing' | 'holiday' | 'special',
  lordsDay: 6, questions: [16, 17], title: '참 사람이시며 참 하나님이신 중보자',
  note: '성찬 주일', isCommunionSunday: true, psalm?: '...' }

// next_generation_school_classes — 반 (seed/jaram/seum/didim)
{ id: 'seed' | 'jaram' | 'seum' | 'didim', name: '씨앗반', ageRule: '영아(4세 이하)',
  verse: '골 2:6', verseText: '...', room: '1층 자모실', order: 1, isVisible: true }
```

- 진도표는 계획안 8장(2027 1학기 23회)을 시드 데이터로 넣고, 2학기 진도표가 확정되면 관리자 화면에서 추가한다.
- 휴강일(설 2/7, 야유회 5/16 예상)도 `kind: 'holiday'`로 넣어 두면, 날짜가 바뀌어도 데이터만 고치면 된다.

### 4-2. 기존 구조 확장

- **반 = 말씀 열매 그룹 ID 통일**: `next_generation_word_fruit_groups`와 교사 `roleProfiles.teacher.groupIds`, 출석 `groupId`가 이미 같은 축을 쓰므로 `seed / jaram / seum / didim`으로 맞춘다. 담임·부담임은 `teacher.groupIds` + `teacher.role: 'homeroom' | 'assistant'`로 표시.
- **출석 확장**: 현재 `{ weekKey, studentUid, present }` → `{ ..., period1?: boolean, period2?: boolean, publicWorship?: boolean }`. 기존 `present`는 `period1`로 읽어 호환.
- **가정 과제**: 문답 암송·디딤반 고백문 확인용. 말씀 열매(`WordFruit`)의 "주 3회 실천 체크" 구조를 **"이번 주 문답 암송"** 체크로 재활용하는 안을 권한다(자람반은 부모가, 세움·디딤반은 학생 본인이 체크).

### 4-3. 공개 범위 (민감 정보)

- 계획안에는 반별 재적 인원, "남은 유치부 전원이 목회자 자녀", 특정 목회자의 자녀 수 같은 내용이 있다. **이는 공개 페이지에 싣지 않는다.** 반 소개는 연령 기준과 운영 방식만.
- 반별 인원·출석·평가 지표는 교사/교역자 로그인 화면에만 보인다.

## 5. 2026 자료 보존 원칙

리뉴얼은 **아무것도 지우지 않는다.** 올해(2025–26) 자료와 기록은 첫 화면에서 보관함으로 옮겨지거나 그대로 이어지며, 삭제·덮어쓰기는 하지 않는다.

### 5-1. 항목별 처리

| 올해 것 | 리뉴얼 후 | 데이터 |
|---|---|---|
| 강의원고, 공과 가이드, 예배를 잇는 가정, 가정예배 | 같은 탭에 그대로 이어짐. 2027 글이 위에 쌓임 | 탭 ID 유지, 변경 없음 |
| 공과(`elementary_workbook`), 여름성경학교 | 메뉴에서 빠지고 "지난 자료" 보관함에서 열람 | 게시물 그대로, 탭만 `isArchived` 표시 |
| 십계명·성경·사도신경 주제 | "2025–26 자료" 묶음으로 주제별 열람 유지 | 주제 문서 유지, 그룹 표시만 추가 |
| 말씀 열매 주차·진행 기록 | 지난 주차 기록 열람 유지 | 컬렉션 그대로 |
| 출석 기록 | 반 대시보드에서 계속 조회. 기존 `present`는 1교시 출석으로 해석 | 필드 추가만, 기존 필드 수정 없음 |
| 질문 있습니다, 가정예배 나눔 | 그대로 | 변경 없음 |
| 회원·역할·반 배정 | 유지. 반 ID 매핑은 새 필드로 추가 | 기존 필드 수정 없음 |
| 소개 페이지의 설교노트·공과·예배를 잇는 가정 사진과 문구 | 새 소개로 교체하되, **"지난 교육 돌아보기"**(2025–26 유초등부) 섹션으로 옮겨 계속 노출 | 이미지 파일 삭제 없음 |

### 5-2. 지켜야 할 규칙

- 기존 Firestore 문서는 **필드 추가만** 하고, 이름 변경·삭제·타입 변경은 하지 않는다.
- 일괄 이관 스크립트가 필요하면 먼저 dry-run으로 바뀔 문서 목록을 출력하고, 실행 전 Firestore 내보내기(백업)를 한다.
- 보관함은 기존 탭 화면을 그대로 재사용한다(새 저장소를 만들지 않음).
- 옛 주소(`/next/elementary`, 기존 게시물 `/next/post/:id`)는 계속 열린다.

### 5-3. 이관 후 확인

- 탭별·주제별 게시물 수가 리뉴얼 전후로 같은지 비교한다(관리자 화면 또는 집계 스크립트).
- 2026년 게시물 무작위 몇 건의 링크·첨부 PDF·유튜브가 열리는지 확인한다.
- 말씀 열매 지난 주차, 지난 출석 주간이 대시보드에서 조회되는지 확인한다.

## 6. 기존 사이트를 유지한 채 병행 준비

리뉴얼 버전은 운영 중인 사이트와 분리해서 준비하고, 개강 직전에 한 번에 전환한다.

### 6-1. 코드: 화면은 복사, 기반은 공유

기존 화면을 새 경로로 복사해 그 복사본을 고친다. 다만 전부 복사하지 않고, **많이 바뀌는 페이지 단위 화면만 복사**하고 거의 바뀌지 않는 기반 로직은 함께 쓴다. 전체(약 2만 줄)를 복사하면 개강까지 두 벌을 관리해야 하고, 운영 중 버그 수정이나 다른 에이전트의 수정이 복사본에 빠지기 때문이다.

| 복사해서 새로 고칠 것 | 원본(운영 유지) | 새 파일(예시) |
|---|---|---|
| 다음세대 페이지 셸 | `src/pages/NextGeneration.tsx` | `src/pages/NextGenerationSchool.tsx` |
| 소개 페이지 | `features/next-generation/IntroPage.tsx` | `features/sunday-school/SchoolIntroPage.tsx` |
| 부서 자료실 | `features/next-generation/ResourceLibraryPage.tsx` | `features/sunday-school/SchoolLibraryPage.tsx` |
| 상단 메뉴 | `features/next-generation/NextGenerationHeader.tsx` | `features/sunday-school/SchoolHeader.tsx` |

  - 켜짐: 메뉴가 `주일학교`로 바뀌고 `/next/elementary` → `/next/school` 리다이렉트.
- 이렇게 하면 작업을 작은 PR로 나눠 main에 계속 합칠 수 있고, 성도에게는 아무 변화가 보이지 않는다. 긴 별도 브랜치에 몰아 두는 방식보다 충돌 위험이 적다.

### 6-2. 데이터: 새 것은 새 자리에

- 학사 일정·진도표·반은 **새 컬렉션**이라 지금 넣어도 기존 화면에 영향이 없다.
- 새 탭(반별 공과 등)은 `isVisible: false` 상태로 만들어 두고, 1월 자료를 미리 올려 둔다. 비공개 자료(`isPublished: false`)로 올려 두고 전환 때 일괄 공개한다.
- 기존 CMS 문서(부서 이름 `유초등부`, 탭 노출, 소개 섹션)는 **전환 때도 수정하지 않는다.** 플래그가 켜지면 코드가 `주일학교` 이름·링크, 소개 블록, 상단 메뉴, `/next/elementary` 리다이렉트, 이용 안내를 알아서 바꾸고, 보관 탭(`ARCHIVED_TAB_IDS`)과 준비 탭(`PREPARATION_TAB_IDS`)도 코드가 처리한다. 그래서 플래그를 끄는 것만으로 완전히 되돌아간다.
- 주의: 운영 사이트와 같은 Firestore를 쓰므로, 미리보기에서 "기존 문서 수정"은 곧 운영 반영이다. 미리보기 단계의 쓰기는 새 컬렉션·새 문서로 한정한다.

### 6-3. 미리보기 주소 (선택)

- 기본은 6-1의 "관리자 로그인 시에만 열림"으로 충분하다.
- 담임목사님·교사회에 로그인 없이 보여 줘야 하면 Firebase Hosting **미리보기 채널**(예: 7일 만료 임시 주소)을 쓴다. 현재 CI(`.github/workflows/ci.yml`)에는 미리보기 채널 설정이 없으므로 추가 작업이 필요하다.

### 6-4. 전환 절차 (2026년 12월 말 ~ 2027-01-03)

1. 당회 승인 사항 반영 확인 → 공개 문구 최종본 입력
2. Firestore 백업 → 관리자 화면 `주일학교` 탭의 "전환 준비 > 보존 점검"으로 5-3 항목 사전 점검
3. 비공개 준비 자료 모두 공개 (관리자 화면 "전환 준비" 버튼, 게시물의 `isPublished`만 바뀜)
4. 플래그 켜기 (같은 화면의 "주일학교 화면 켜기", 사이트 관리자만 가능) → 메뉴·리다이렉트·소개·이번 주일 카드·이용 안내를 모바일 포함해 확인
   - 처음 이용 안내(튜토리얼 팝업)는 주일학교용 단계를 코드에 구현했다(완료). 플래그가 켜지면 "주일학교"가 첫 선택지로 나온다.
5. 문제가 생기면 **플래그만 끄면 기존 화면으로 즉시 복귀**한다. CMS 문서를 바꾸지 않았고 데이터도 지우지 않았으므로 되돌릴 것이 없다. (공개로 바꾼 준비 자료는 그대로 공개 상태로 남는다.)

### 6-5. 전환 후 정리 (2027년 1월 중순~말)

- 개강 후 2~3주 동안 문제가 없으면 플래그 분기를 없애고, 원본 화면 4개 파일(`NextGeneration.tsx`의 유초등부 분기, `IntroPage.tsx`, `ResourceLibraryPage.tsx`, `NextGenerationHeader.tsx`)을 삭제한다. 청년부 화면이 원본을 쓰고 있으면 새 화면으로 옮긴 뒤 삭제한다.
- 정리는 코드만 지운다. 데이터와 `/next/elementary` 리다이렉트, 2026 보관함은 그대로 둔다(5장).

## 10. 이번 주 문답 여정과 성경 읽기 (2026-11-13 결정)

말씀 열매 기능(주차·실천 체크·열매 연출·반 그룹·진행 기록)은 지우지 않고 아래 두 기능의 바탕으로 다시 쓴다. 올해 말씀 열매 기록은 그대로 보존한다. 구현은 8장 5단계(1학기 운영 중)에 한다.

### 10-1. 이번 주 문답 여정

이번 주 하이델베르크 문답(진도표에서 자동) 하나를 중심으로 주일부터 다음 주일까지를 네 단계로 잇는다.

| 단계 | 내용 | 채우는 방법 | 횟수 |
|---|---|---|---|
| 배움 | 이번 주 문답 강해·공과 | **교사 출석 체크로 자동**(1교시 출석 기준) | — |
| 가정예배 | 가정예배지로 가정예배 | 부모, 날짜별 체크 | 1회면 완료, 여러 번 가능 |
| 실천 | 공과 시간에 아이가 **각자 약속한 실천** | 씨앗·자람: 부모 / 세움·디딤: 학생, 날짜별 체크 | 1회면 완료, 여러 번 가능 |
| 암송 | 지난주 문답 암송 | **교사가 다음 주일에 확인** | — |

- 반별 실천
  - 씨앗반: 약속 대신 "주일에 함께 읽은 말씀 동화를 주중에 다시 읽기"로 고정한다.
  - 자람반: 부모와 함께 실천한다.
  - 세움·디딤반: 각자 실천한다.
- 실천 약속 입력: **모든 반 교사 입력**으로 시작한다(디딤반 포함). 본인 입력은 운영해 본 뒤 다시 정한다.
  - 교사는 아이가 말한 약속이 너무 쉽거나 막연하면 실천할 수 있을 만큼 구체적으로 다듬도록 이끈다.
  - 교사 입력칸 옆에 짧은 안내를 둔다.
    - 언제: 아침에, 잠들기 전에
    - 누구에게: 동생에게, 부모님께
    - 무엇을: 문답과 이어진 행동 하나
    - 몇 번: 이번 주 3번
  - 이번 주 문답에서 나온 예시 약속 1~2개를 보여 준다. 교역자가 공과 가이드를 쓸 때 함께 적는다.
- 암송 수준(반별):
  - 씨앗: 없음(동화 다시 읽기로 대신)
  - 자람: 질문 + 핵심 한 구절
  - 세움: 질문 + 답의 핵심 문장
  - 디딤: 질문 + 답 전체
- 한 주에 여러 문을 배우면 암송할 문 하나를 정한다. 디딤반은 나머지 문을 "도전"으로 둔다.
- 진도표 각 주에 "암송 문항"과 반별 암송 문구 칸을 더한다. 여정 화면에는 아이 반 문구만 보인다.
- 자람반 핵심 구절은 공과 원고·공과 가이드를 쓸 때 정한다.
- 번역본: 미정. 화면에 문구를 올리므로 사용 허락을 확인해야 한다.
- 「예배를 잇는 가정」: 부모에게 드리는 칼럼이므로 체크하지 않는다. 여정 화면에 링크로만 둔다.
- 기록 공개 범위
  - 아이·부모는 자기 가정 기록만 본다.
  - 교사는 **자기 반 아이별 횟수**를 본다.
  - 반끼리 비교나 순위는 보여 주지 않는다.
  - 화면은 숫자보다 그 주 달력의 도장(가정예배·실천한 날)으로 보여 준다.
- 방학 모드에서는 단계가 바뀐다(공예배 참석·가정예배·지난 문답 복습). 디딤반 고백문은 개편안대로 방학 과제로 두고 개학 주일에 확인한다.

**교사의 주일 반 화면**(아이 한 줄마다):
- 출석 토글(→ 배움 자동)
- 지난주 암송 확인
- 지난주 가정예배·실천·성경 읽기 기록
- 이번 주 실천 약속 입력(씨앗반 제외)

### 10-2. 성경 읽기 (1년 1독)

현재 기록표의 문제:
- 마이페이지 안에서 학생 계정에게만 보인다.
- 교역자만 색을 칠할 수 있다.
- 66권 단위라 매주 변화가 보이지 않는다.

개선:
- 대상: **세움·디딤반부터**. 자람반은 별도 목표(어린이 성경, 신약 등)를 더 고민한다. 씨앗반은 대상이 아니다.
- 계획: **창세기부터 순서대로** 1년 1독(하루 약 3~4장, 주 단위 목표). 맥체인은 청년부에 권한다(오늘의 말씀).
- 체크: 장 단위, 날짜별. 반별로 체크하는 사람을 다르게 둔다.
  - 세움반: **아이와 부모 모두** 같은 기록에 체크할 수 있다. 휴대폰을 자유롭게 쓰지 못하는 아이가 있기 때문이다.
  - 디딤반: 학생 본인이 체크한다. 체크하려면 `next_generation_bible_reading` 쓰기 규칙을 넓혀야 한다(공유 파일 `firestore.rules`).
- 한 권을 다 읽으면 기존 66권 책장 그림에 색이 칠해진다. 기존 그림을 재사용한다.
- 접근성
  - 주일학교 첫 화면에 "올해 성경 읽기" 띠를 둔다(올해 진도, 이번 주 분량).
  - 부모 계정에서 자녀 기록을 볼 수 있게 한다.
  - 교사 반 화면에 아이별 "지금 어디까지"를 보여 준다(확인용).
- 해마다 새로 시작한다. 2026 기록은 "지난 기록"으로 보존한다.
- **개별 과제**로 운영한다. 반 나눔은 하지 않는다.
- 읽는 방식: 날짜와 상관없이 **마지막으로 읽은 장 다음부터 순서대로** 이어 읽는다.
  - 날짜별 계획은 목표선으로만 쓰고, 밀린 것을 따로 경고하지 않는다.
  - 체크할 때 "어디까지 읽었는지"를 고른다.
- 화면 구성
  - **이번 주 카드**(위): 오늘 분량, 이번 주 분량, 요일 도장, "다음 읽을 곳", "다 읽었어요" 버튼
  - **1년 진도 한 줄**: 읽은 장 / 1,189장, 진도 막대와 오늘 계획선
  - **책장**(아래, 기존 그림 재사용): 각 책 모양 안에서 읽은 비율만큼 색이 찬다(세운 책은 아래→위, 눕힌 책은 왼→오른쪽). 다 읽으면 책 전체를 칠하고, 지금 읽는 책에 책갈피를 표시한다.

### 10-3. 남은 결정
1. 암송 번역본
2. 자람반 성경 읽기 목표: 아이마다 이미 읽은 어린이 성경 단계가 달라 개별 목표가 필요할 수 있다. 계속 논의한다.
3. 학생 계정이 할 수 있는 일의 범위. 학생 계정은 이미 있다.
   - 가입 시 `학생` 역할을 고르고 부모 이메일을 넣으면, 승인할 때 부모 계정과 자동으로 연결된다.
   - 지금은 공과 탭만 볼 수 있다. 새 주일학교 화면에서는 반별 공과와 공통 강해 원고까지 넓혔다.
   - 여정 실천 체크와 성경 읽기 체크를 허용한다. 약속 입력은 교사가 한다(10-1).
