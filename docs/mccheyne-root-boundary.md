# 승인 루트의 상위 메타데이터 경계

최소 공유를 받은 Reader에게 승인 루트의 `parents` 속성이 생략될 수 있다. 이 경우만 아래의 정확한 ID 경계를 적용한다.

## 변경과 유지한 경계

- 승인 루트 ID `1XxgBRwigRQmgGgk_mvXQBVUqen51iARX`를 고정된 범위 기준으로 사용한다. 이 정확한 루트의 메타데이터에서 `parents` 속성이 **아예 없을 때만** 상위 정보 검사를 생략한다. ID·폴더 MIME·휴지통 검사는 먼저 수행한다.
- `parents`가 있다면 배열 한 개이며 기대하는 상위 ID `1VWRtAD--dJVIsZOh7VNsDSPLO6UQYZMC`와 일치해야 한다. 빈 배열, null, 명시적 undefined, 문자열, 배열 흉내 객체, 여러 부모, 실제 다른 부모는 계속 거절한다. 정상적인 JSON 응답의 속성 부재와 잘못된 값을 구분한다.
- 연도 폴더에는 예외가 없다. 승인된 2026/2027/2028의 세 정확한 ID만 처리하며 실제 부모는 승인 루트여야 한다. 각 문서도 허용된 네 폴더 중 하나의 직접 자식이어야 한다. 이름이 같은 다른 폴더, 임의 깊이, shortcut을 따라가지 않는다.
- 폴더/문서의 malformed parents 배열 흉내, 잘못된 trash 타입, 숫자 문서 ID/버전/수정 시각을 거절하도록 런타임 형식 검사를 보강했다. 새로운 읽기 대상이나 API 요청은 추가하지 않는다.

목록에 들어온 사실만으로 게시 승인을 부여하지 않는다. 기존의 정확한 이동 대상·승인자·시각 검사와 이동 후 변경 검사, sourceHash 재승인, 관리자 ID 토큰/현재 관리자 판정, 고정 작성자 UID, 수동 글 충돌, 사이트 수정/삭제 보류와 트랜잭션 검사는 그대로 유지한다. 이 수정은 폴더 범위의 판정만 변경한다.

## 남는 한계와 대안

제한된 Reader에게 root의 parents가 보이지 않으면 **그 root 자체가 다른 외부 위치로 이동했는지 항상 탐지할 수 없다.** 같은 root 고유 ID와 그 안의 승인 문서가 계속 기준이 된다. 이는 원래 상위 경로에 계속 위치한다는 보장과 다르다. 반대로 실제 다른 parent가 응답에 보이면 현재처럼 중단한다.

기존의 누락도 무조건 중단하는 방식은 보수적이지만 확인된 최소 공유 설정에서 자동화가 계속 막힌다. 별도 사용자 계정의 주기적 경로 검증은 다른 지속 인증·운영 구성을 요구하므로 이번 최소안에 추가하지 않는다. 상위 초안 폴더 공유 확대도 하지 않는다. 실제 승인자 이동 증거의 가시성은 별도의 비게시 운영 확인 대상이다.
