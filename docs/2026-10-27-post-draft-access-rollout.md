# 게시글 초안 접근 제어 배포 준비

상태: 수정·검증 및 읽기 전용 사전 점검 단계. 운영 데이터 보정, 인덱스·규칙·API·Hosting 배포, PR 병합은 아직 실행하지 않았다.

## 변경 이유와 범위

PR #116의 draft 표시가 실제 접근 제한으로 연결되지 않았다. 비설교 글을 모두 공개하던 `canReadPostData`를 수정해 관리자 또는 게시된 글의 기존 읽기 자격을 확인한다. 본문·PDF 조각에도 부모 규칙이 적용된다. 공개 페이지에는 `isPublished == true` 쿼리를 추가하고 기존 복합 인덱스를 보존하면서 게시 상태가 포함된 인덱스를 추가한다.

`settings/latest_posts_summary`에 남은 이전 본문 일부도 공개하지 않도록 관리자 전용으로 제한한다. 공개 홈은 원본 글을 조회한다. API가 게시된 글을 draft로 돌릴 때 그 글의 내부 요약은 트랜잭션에서 제거한다. 공개 홈의 이전 로컬 캐시도 더 이상 사용하지 않는다.

관리자는 상세 URL과 맥체인 날짜 화면에서 초안을 계속 확인할 수 있다. 기존 공개 글의 작성자·날짜·본문·조회수는 보정하지 않는다. 신규 공개 작성 경로들은 이미 `isPublished: true`를 저장한다.

## 사용자 승인 후 적용 순서

현재 main 병합은 Hosting 자동 배포를 유발한다. 아래 사전 작업 전에 PR을 병합하지 않는다.

1. 새 게시 상태 인덱스를 추가하고 READY까지 확인한다. 기존 운영 인덱스와 대조하며 삭제는 하지 않는다. 인덱스 준비 전 새 쿼리를 운영에 적용하면 목록이 실패할 수 있다.
2. `scripts/prepare-post-publication.mjs`를 기본 읽기 전용 모드로 실행해 대상 수를 다시 확인한다. 명시적 승인 후에만 `--apply`로 필드가 **없는 글만** `isPublished: true`로 보정한다. 현재 true/false 또는 잘못된 자료형은 덮어쓰지 않는다. 문서 updateTime precondition으로 동시에 변경된 글을 덮어쓰지 않으며 충돌 시 중단하고 재점검한다. 재실행은 이미 보정한 글을 건너뛴다.
3. 보정 후 missing/invalid가 0인지 확인한다. 이 조건이 만족되지 않으면 새 규칙·Hosting 배포를 중단한다.
4. 승인된 수정 PR을 병합하고 Hosting CI·공개 목록을 확인한다. 아직 규칙을 적용하기 전까지 초안은 비공개로 간주하지 않는다.
5. named DB의 Firestore 규칙과 `functions:raah:siteApi`만 명시적으로 배포한다. Functions는 Hosting CI로 배포되지 않는다. 예약 함수·RAAH·Storage 규칙·IAM·비밀값은 대상이 아니다.
6. 관리자/익명/회원별 목록·상세·본문 조각·홈, 설교 제한을 확인하고 기존 기능 회귀를 확인한다. 실운영 테스트 글을 새로 쓰거나 자동 발송하지 않는다. 별도의 운영 시험 데이터가 필요하면 범위를 먼저 정한다.

사용 예시: 짧은 수명의 `GOOGLE_ACCESS_TOKEN`을 안전하게 프로세스 환경으로 전달한 뒤 `node scripts/prepare-post-publication.mjs`를 실행한다. 토큰을 명령 인수나 로그에 쓰지 않는다. 보정 실행은 `--apply`를 추가한다. 스크립트는 위 프로젝트/DB에 고정되며 기본 모드는 읽기 전용이다.

## 검증과 한계

- 각주 회귀: 공백 1~3개 및 탭으로 들여쓴 정의, 연속 줄, 빈 줄 뒤 각주 문단, CRLF, 보존할 다음 본문.
- Firestore 에뮬레이터: 익명·정회원·작성자의 초안/조각 get·list 거부, 관리자 허용, 게시→초안 전환 즉시 차단, 공개 쿼리 허용, 레거시 보정 전 거부/후 허용, 설교 회원 제한 유지, 요약 문서 거부.
- 보정 단위 테스트: dry-run 무변경, 필드 없음만 보정, 명시적 false 보존, 동시 변경 precondition 실패 시 무조건 재시도하지 않음.
- 기존 댓글 트랜잭션 검사는 실제 프로필처럼 작성자에 한정한 조회로 검증한다. 권한 없는 전체 컬렉션 조회를 성공 조건으로 삼지 않는다.
- 현재 열려 있는 브라우저나 이미 내려받은 콘텐츠는 소급 회수할 수 없다. 인증된 관리자에게 전달된 내용을 로그아웃 후 다시 불러오지 않도록 상세 화면도 상태를 확인한다.
- Firebase 에뮬레이터는 운영 복합 인덱스 READY를 검증하지 않으므로 운영 인덱스 확인은 별도 필수다.

## 복구

게시 상태 true 보정은 기존 공개 글의 의미를 명시한 것이므로 되돌리지 않는다. 접근 문제 발생 시 새 규칙을 공개로 풀기보다 누락된 인덱스·게시 필드·쿼리를 점검한다. 코드 롤백이 필요하면 보안 규칙과 맞는 쿼리를 유지하는 복구 PR을 사용한다. 기존 무조건 공개 규칙으로의 복귀는 별도 보안 판단이 필요하다.
