## 아직 완료되지 않은 계획 항목

1. **기존 자료·사진의 읽기 권한 전환:** pdfs/materials/sermons의 공개 읽기, 가정예배 사진의 기존 읽기 범위와 토큰 URL은 그대로다. 기존 파일 소유자·가족/교사 관계 확인, 공유 URL 회수, 인증된 다운로드 방식 전환이 필요하다. 이번 쓰기 권한 보강을 읽기 유출 위험 해결로 보고하면 안 된다.
2. **게시글 비공개·예약·대상자 제한:** Firestore의 canReadPostData 정책은 이번에 전환하지 않았다. 필드 누락 문서의 기본값과 목록 쿼리/요약/첨부 접근을 함께 이전해야 한다. 규칙만 강화하면 기존 목록 조회가 거절될 수 있어, 데이터 이전 없이 적용하지 않았다.
3. **RAAH 조회 성능의 최종 구조:** 내부 페이지 조회로 잘림은 완화했지만 bootstrap은 여전히 여러 목록을 모은다. 기간별 집계·UI 커서 페이지네이션·필요 시 상세 로딩은 추가 작업이다. 서버 조회는 20,000건 수준에서 오류를 반환하여 조용한 잘림을 막으며, 이를 무제한 규모 대응으로 해석하지 않는다.
4. **전체 대형 파일 분리·strict 전환·린트 경고 해소:** 공통 인증/요청/예약 실행은 추출했으나 1,000행 이상 화면을 모두 분리하지 않았다. 회귀 테스트를 늘리며 기능별로 진행할 작업이다.
5. **의존성 취약점:** 후속 작업에서 npm 11.6.2를 사용해 기존 범위 안의 보안 패치를 적용했다. 27건(critical 1/high 9/moderate 15/low 2) → 8건(moderate 8, 나머지 0). Firebase Admin 전이 의존성의 uuid 권고가 남아 있다. 강제 override는 하지 않았다. Admin 14는 namespace API 제거와 Node 22 이상 요구가 있어 서버 코드 이관·배포 런타임 확인을 별도 진행해야 한다.
6. **기존 외부 자료 정리:** 이전에 Gemini로 전송되거나 Google Calendar에 저장된 메모의 삭제·보관 정책은 이번 코드 변경으로 소급 처리하지 않는다. 새 전송 경로만 제한했다.

## 배포 전후 순서

이 문서는 배포 허가를 의미하지 않는다. 명시적 요청 후 다음 순서로 진행한다.

1. 테스트 프로젝트 또는 승인된 프리뷰에서 Firebase 관리자·일반 사용자·다음세대 역할별 흐름을 확인한다.
2. 새 함수와 클라이언트를 먼저 배포한다. 댓글 작성/삭제, PDF 업로드, RAAH 저장/조회와 캘린더 연결 상태를 확인한다.
3. 새 Firestore·Storage 규칙을 적용한다. 구버전 화면을 새로고침한 후 같은 흐름을 재확인한다. Netlify 배포만으로 Firebase 규칙이 자동 적용되는 것은 아니다.
4. 예약 알림 processing/needs_review를 확인한다. 결과 불확실 알림을 일괄 pending으로 돌리지 않는다.
5. 장애 시 함수·화면·규칙의 대응 버전을 함께 고려한다. 새 규칙을 유지한 채 댓글 API 없는 구버전 앱으로만 되돌리면 댓글 기능이 막힌다. 인증 우회가 있던 이전 RAAH 핸들러로의 단순 복귀는 피한다.

- **다음세대 진입:** 다음세대 회원 문서가 없다는 이유로 공유 Firebase Auth 계정을 삭제하던 처리 제거. 기존 일반회원은 추가 정보 입력 후 승인 대기로 진행한다. 이메일/Google 제공자 구분을 유지하고, 이용 안내가 로그인/가입 안내를 가리지 않게 했다.
